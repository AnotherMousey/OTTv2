# Engine-generated finished samples

Open `frontend/preview.html` → Replay → Finished sample matches, or Import a file from `samples/matches`.

Every match JSON was generated by applying the listed actions to the actual game engine. No terminal winner was invented in the frontend. Generation fixes wall-clock time for reproducibility, so these fixtures test rules and moves rather than clock passage. Real clock/forfeit behavior is covered by the room integration tests.

## Maps

| File | Size | Pieces per side |
|---|---|---|

| `maps/standard-9.json` | 9×9 | 9 |

The submission form provides these maps. Small and large finished samples demonstrate the changed geometry and piece counts. Goal/capture scenarios use purpose-built valid initial positions to reach their outcomes clearly; they are not claims of bot-generated tournament performance.

`scenarios/` stores each exact configuration, legal moves and expected ending. `matches/` contains the resulting viewer-importable replay. `bots/` contains Java, C++ and Python examples with dynamic board-size support. `renderers/grid-demo.json` retains the approved second-renderer acceptance fixture; unlike the nine OTTv2 matches, it is only a renderer demonstration.

Reproduce all nine matches: `npm run samples`. Verify every frame and terminal result: `npm test`. After changing a map or scenario, commit the regenerated frontend sample/map JSON so Vercel's frontend-only build receives the new catalog.
